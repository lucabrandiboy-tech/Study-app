# Study + Piano

A study and piano-practice app for an 8th grader: full courses for each subject, a homework calendar, an A+ Plan, a search bar (app content, Wikipedia look-ups and picture search, all shown inside the app), and a piano course with a 1,000+ song library. Dark UI. It runs in the browser, on phones and computers, with no API key needed.

## Stack
React 18 + Vite + TypeScript (strict, `noUnusedLocals`), Tailwind 3, react-router (HashRouter in the single-file build), Tone.js (piano sound + generated smooth-jazz background music on every page, on by default, `settings.jazz`; pauses only while a YouTube video is open or the app is listening to a song), OpenSheetMusicDisplay (sheet music), @tonejs/midi, Recharts, qrcode-generator.

## Commands
- `npm run dev:web`: dev server (port 5173)
- `npx tsc -b`: typecheck (run before every commit)
- `npm run check`: validates every study question generator, every song's bar lengths, and a few search results (run before every commit)
- `npm run build:single`: one self-contained HTML file in `dist-single/index.html`. Copy it to `study-piano-app.html` (gitignored) to hand to the user.
- `npm run build:pwa`: installable phone app in `dist-pwa/` (manifest, icons, offline service worker)

## Where things live
- `src/lib/store.ts`: all app state (localStorage, `useSyncExternalStore`). Includes settings, topics, streak, homework, grades, tests, spaced review, piano progress. `normalize()` fills new fields on load, so add defaults to `fresh()`.
- `src/study/`: subjects and topics. `subjects.ts` builds each course from units; `bank.ts` (`bankTopic`) turns question banks into generators; `QuestionView.tsx` renders questions; `APlan.tsx` (daily review, tests, grades); `Calendar.tsx` (its own sidebar tab + 📅 on phones: a Sunday-first month calendar; tap a day to add an assignment and pick its subject in `DayEditor`; unfinished homework due tomorrow or earlier blocks that day's streak).
- `src/piano/`: `course.ts` (units and lessons), `songs.ts` and `library/*` (song library; `make.ts` holds the compact song format, `popGen.ts` generates the original pop songs, `preAdvanced.ts` holds the hand-written pieces), `engine.ts` (play modes), `SimplyPlayer.tsx` (full-screen player), `importer.ts` (MusicXML/.mxl/MIDI import), `listen.ts` + `YouTubeImport.tsx` (▶️ From YouTube: YouTube's official player in `components/MiniPlayer.tsx`, mounted in App so it keeps playing across pages, sandboxed with no popups; 🎧 Listen to this computer hears the computer's own sound through the browser's tab/screen sharing with tab audio (`getDisplayMedia`, so it works with headphones; computers only, Chrome/Edge) and 🎤 Listen with mic hears the room; either turns the melody into an Imported song — no downloading from YouTube), `input.ts` (MIDI keyboard + computer keys).
- `src/pages/Search.tsx`: Search page (`/search`, sidebar box, 🔍 on phones, Ctrl+K). Results open in a preview on the page instead of navigating away. `src/lib/search.ts` indexes the app's content and the student's own homework/notes/decks (local only); `src/lib/wiki.ts` is the "Look it up" and "Pictures" part: Wikipedia's and Wikimedia Commons' public APIs (no key, `origin=*` CORS); article text and pictures are shown inside the app, never linked out. Commons has no safe-search, so `unsafeText()` filters picture searches, file names, descriptions and categories (the user is an 8th grader). Settings > 👩‍🏫 Teacher mode (PIN, `settings.picFilter` false, fixed PIN checked against `TEACHER_PIN` in `pages/pages.tsx`, stored only as its `pinHash`; `settings.picPin` is no longer used) turns the filter off. `src/lib/sources.ts` adds more keyless sources (Openverse, NASA images, Art Institute of Chicago, Wiktionary, Open Library), also shown only inside the app and filtered the same way. The filter blocks nudity/sexual content/extreme gore but lets school topics through (`SCHOOL` phrases). With the filter off (teacher PIN), `src/lib/web.ts` adds 🌍 Web: Marginalia's keyless search API, DuckDuckGo instant answers (JSONP) and r.jina.ai to read any page as plain text inside the app. The service worker never caches any search source. Search is private: search words never go in the URL (sidebar passes them as one-time router state), are never stored by the app, the search boxes are `PrivateField` (contenteditable, not `<input>`, so browsers have no form history/autofill to save), and look-ups use `cache: 'no-store'`.
- `src/lib/localTutor.ts`: offline rule-based Study Buddy (teaches from lesson data, never gives homework answers).
- `src/lib/cloud.ts`: cloud save when the app runs as a claude.ai artifact (per-user private `db` storage, chunked, newest copy wins). `src/lib/filesave.ts`: save files, downloads, daily auto-backup.
- `src/components/`: Shell (sidebar + phone top bar/drawer), GeoTools (notepad + TI-84 style calculator on study pages), Reminders (popup on open), PhoneSetup (install QR code).
- `src/index.css`: phone layout rules (`@media (max-width: 767px)`).
- `robot-voice/`: Robot Voice, a separate app on the same site (https://lucabrandiboy-tech.github.io/Study-app/robot-voice/), built by `npm run build:robot` (part of `build:pwa`) into `dist-pwa/robot-voice/`. `page.html` is the whole app (G opens a talk box in a modal `<dialog>`, so it sits on the browser's top layer; typed lines are spoken by eSpeak with a flat-pitch "robot" voice in `voice-worker.cjs`, a Web Worker bundled with esbuild from the `mespeak` package, GPL; effects are baked offline and loudness-levelled). Mic modes: voice changer (`vocoder-worklet.js`, an AudioWorklet: 22-band vocoder where the mic shapes a sawtooth at the robot's pitch; it levels the mic and gates noise itself, so the browser's noise suppression/auto-volume are off; `node`-runnable for testing), talk instead of type (browser SpeechRecognition, skips what it hears while the robot talks out loud), and "Friends hear it" (copies the output to a picked device with `setSinkId`, e.g. VB-CABLE's CABLE Input). The same `page.html` is also the claude.ai artifact https://claude.ai/artifact/13GyWMCX6PKiKSq4Lde9pA (published with `voice-worker.js` as a file); claude.ai blocks the mic, so there it shows a link to the full app. `pwa/sw.js` leaves `robot-voice/` alone.
- `recedo/`: Recedo, a separate Krita-style painting app for Windows (Rust: Win32 + wgpu + egui), built phase by phase from the user's spec; nothing to do with the Study app's build. The spec's working rules apply: never call a feature working unless it was run and verified, keep `recedo/FEATURES.md` (status of every feature) and `recedo/DECISIONS.md` up to date, and stop at the end of each phase for the user's go. Phase 0 is the tablet test app (`recedo-tablet-test.exe`). Build, test and self-test commands are in `recedo/README.md`; `recedo/rust-toolchain.toml` pins Rust; `.github/workflows/recedo.yml` lints, tests and cross-compiles on Linux and runs the self-test on Windows.

## Conventions
- Use `ask()` from `src/lib/embed.ts` instead of `confirm()`. Pop-up dialogs are blocked when the app runs inside the claude.ai viewer.
- Songs use the token format `C4:q`, `[C4 E4]:h`, `r:e`, `~` ties, `.` dots, `t` triplets; `|` separates bars. `npm run check` catches bad bar lengths.
- Study never solves homework: lessons, worked examples, generated practice, hints.
